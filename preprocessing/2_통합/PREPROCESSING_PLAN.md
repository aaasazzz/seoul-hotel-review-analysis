## 2. 처리 순서

```
6개 파일
 ① 병합 · 표시 컬럼 추가
 ② 공백 정리
 ③ 반복 문자 줄이기
 ④ 토큰화 (사용자 사전 + 품사 거르기 + 원형)
 ⑤ 부정어 묶기
 ⑥ 동의어 통일
 ⑦ 불용어 제거
 ⑧ 블로그 문장 단위 파일
 → 결과 저장 + 로그
```

### ① 병합 · 중복 제거 · 표시 컬럼 추가
6개 파일을 하나로 합친 뒤 **중복을 지우고**(팀 기준 `reviewer_id + review_date + review_text_raw`, 같은 플랫폼 안에서만 비교, 처음 것만 남김 → `로그/duplicate_log.csv`) 아래 컬럼을 덧붙임

| 컬럼 | 내용 | 기준 |
|---|---|---|
| `hotel_std` | 표준 호텔명 (`hotels_seoul.csv`의 32곳) | `사전/hotel_alias.csv` (예: Grand Hyatt Seoul, 더그랜드롯데 서울 → 각각 그랜드 하얏트 서울, 롯데호텔 서울) |
| `in_period` | 기간 안이면 Y, 아니면 N | `review_date`가 **2024-10-01 이후면 Y**. N은 유튜브 옛날 댓글 1,125건 (2021-10 ~ 2024-09) |
| `is_short` | 10자 미만의 짧은 리뷰 | "좋아요", "굿" 같은 정형 리뷰 표시 |
| `is_ad` · `ad_reason` | 광고성 글·협찬·가짜 의심 | 블로그: 협찬 고지("업체로부터 제공받아 작성" 등, "협찬 없이" 같은 부정은 제외) · 제휴 수수료 고지 · 최저가 예약/할인 코드 홍보 / 전체: 같은 작성자가 같은 글(20자 이상)을 여러 호텔에 올린 복붙 의심 |
| `hotel_mentioned` | 본문에 해당 호텔명이 나오는지 (블로그·유튜브) | 호텔 관련 없는 글 걸러내기용 (결과_설명.md 통계에만 씀) |
| `is_noise` | 호텔 이야기가 아닌 유튜브 댓글 | 채널 반응·무관·미경험 희망 → Y. `youtube_noise.py` 규칙 1차 판정 + `사전/yt_labels.csv` 최종 판정 (7장) |
| `rating_5` | 5점 기준 평점 | 4종 모두 5점 기준 값 그대로 (여기어때·아고다는 WS가 5점 환산해 둠) |

참고: 2025-01-01 기준으로 보려면 분석 단계에서 `review_date >= 2025-01-01`로 거르면 됨 (블로그·여기어때·아고다의 2024-10~12 글 2,365건 차이)

### ② 공백 정리
- 연속된 공백·탭 → 한 칸, 앞뒤 공백 제거
- 빈 줄이 여러 개면 한 줄로 (줄바꿈 자체는 문장 나누기에 쓰므로 남김)
- **오탈자 교정은 하지 않음** (개인 단계 결과를 존중)

### ③ 반복 문자 줄이기
같은 글자가 3번 이상 반복되면 2번으로 줄임
- ㅋㅋㅋㅋㅋ → ㅋㅋ, ㅠㅠㅠㅠ → ㅠㅠ, ㅎㅎㅎ → ㅎㅎ
- !!!! → !!, ???? → ??, ~~~~ → ~~, ..... → ..
- **ㅋㅋ·ㅎㅎ·ㅠㅠ는 지우지 않음**

URL·해시태그·유튜브 타임스탬프(12:46)는 따로 지우지 않음. 키위가 각각 별도 종류(URL, 해시태그, 일련번호)로 분류해서 ④의 품사 거르기에서 자동으로 빠짐. 해시태그는 `#`만 떼고 단어(#호캉스 → 호캉스)는 살림

### ④ 토큰화
- **사용자 사전** (`사전/user_dict.csv`): 키위가 잘못 쪼개지 않게 등록
  - 호텔·브랜드: 시그니엘, 파크하얏트, 반얀트리, 조선팰리스 …
  - 업장·시설: 더파크뷰, 이그제큐티브라운지, 어반아일랜드, 인피니티풀 …
  - 리뷰 표현: 호캉스, 가성비, 가심비, 얼리체크인, 레이트체크아웃, 어메니티, 턴다운, 뷰맛집 …
  - 개인 교정 단계(`1_개인교정/preprocess_correct.py`)의 사용자 사전을 이어받아 확장
- **남길 품사**

  | 품사 | 키위 표시 | 예 | 처리 |
  |---|---|---|---|
  | 일반·고유명사 | NNG, NNP | 조식, 수영장 | 그대로 |
  | 동사·형용사 | VV, VA (불규칙 포함) | 맛있었어요, 좁아서 | **원형**: 맛있다, 좁다 |
  | 어근 | XR | 깔끔(하다), 친절(하다) | 그대로 |
  | 부사 | MAG | 정말, 너무, 다시, 별로 | 그대로 (불용어 단계에서 정리) |
  | 영어 | SL | view, lounge | 소문자로 |
  | 자모 표현 | SW 중 ㅋ·ㅎ·ㅠ·ㅜ | ㅋㅋ, ㅠㅠ | 그대로 |
  | 해시태그 | W_HASHTAG | #호캉스 | `#` 떼고 다시 분석 |
- **버리는 것**: 조사, 어미, 접사, 문장부호, 숫자, URL, 타임스탬프, 기타 기호

### ⑤ 부정어 · 재방문 표현 묶기
| 원문 | 토큰 |
|---|---|
| 안 좋았어요 | `안_좋다` |
| 좋지 않았다 | `안_좋다` |
| 못 쉬었다 | `못_쉬다` |
| 편하지 못했다 | `못_편하다` |

"별로", "그닥" 같은 부정 부사는 그 자체로 토큰으로 남김

재방문 의사도 묶음 ('또', '오다', '방문'이 불용어라 묶지 않으면 통째로 사라짐)

| 원문 | 토큰 |
|---|---|
| 다음에 또 올게요 / 다시 방문할게요 / 재방문 의사 있어요 | `재방문` |
| 다시는 안 올 것 같아요 | `안_재방문` |

### ⑥ 동의어 통일 (`사전/synonyms.csv`)
1. ④~⑤까지 실행한 결과로 **빈도 상위 300개 단어** 추출
2. 그중 같은 뜻의 단어를 묶은 **초안** 작성 (예: 직원분·스태프 → 직원 / 아침식사·조식뷔페 → 조식 / 전망·야경 → 뷰 / 깨끗·청결·깔끔 → 청결)
3. **분석 담당 팀원이 확정**한 뒤 적용

### ⑧ 문장 단위 버전
6종 전체를 키위 문장 나누기(`split_into_sents`)로 나눈 뒤, 문장마다 ②~⑦을 똑같이 적용해 `merged_sentences.csv`(문장 1개 = 1줄)로 저장. 글 단위 `tokens`는 그 글의 문장 토큰을 이어 붙인 것과 **정확히 같음** (두 버전이 같은 기준). 이유는 3장

## 3. 블로그를 문장 단위로도 나누는 이유

블로그 글 1편은 평균 약 2,000자이고, 한 글 안에 **객실·조식·수영장·라운지·주변 맛집·교통**이 모두 나옴. 다른 데이터는 리뷰 1건이 40~80자(1~2문장). 블로그를 글 단위로만 토큰화하면 네 가지 문제가 생김

| 문제 | 예 | 문장 단위로 하면 |
|---|---|---|
| **엉뚱한 단어끼리 연결됨** | "조식은 정말 맛있었다. … (20문장 뒤) … 주차장은 별로였다" → 글 단위로는 '조식'과 '별로'가 같은 글에 함께 나와, 연관어 분석에서 **조식이 별로였다**처럼 잡힘 | 같은 문장 안의 단어끼리만 연결 → "조식-맛있다", "주차장-별로" |
| **글 1편이 너무 많은 비중을 차지** | 2,000자 글 1편이 짧은 리뷰 수십 건만큼 단어를 쏟아냄 → 블로그 몇 편의 표현이 전체 빈도를 좌우 | 문장 수로 비중을 볼 수 있음 |
| **호텔과 무관한 내용이 섞임** | 여행 일정, 다른 식당·관광지, 가족 이야기 | 호텔 관련 단어가 있는 문장만 골라 쓸 수 있음 |
| **주제별로 모으기 어려움** | "조식에 대해 사람들이 뭐라고 했나"를 보려면 글 전체를 읽어야 함 | "조식"이 들어간 문장만 모아 그 문장의 형용사·부사를 보면 됨 |

문장 단위로 나누면 블로그의 처리 단위가 다른 플랫폼 리뷰(1~2문장)와 비슷해져서 **같은 기준으로 비교** 가능. 글 단위 `tokens`도 그대로 만들어 두므로, 글 단위 분석이 필요하면 그것을 쓰면 됨

비용: 블로그 1편이 수십 문장이라 문장 파일은 수십만 줄이 됨. 그래서 통합본과 별도 파일로 둠
